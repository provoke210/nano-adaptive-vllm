# GPU 第二轮：数值一致性与自适应调度

日期：2026-10-21。RTX 3090 24GB，Qwen3-0.6B，FP16；PyTorch 2.8.0+cu128、Triton 3.4.0、Transformers 4.55.2、FlashAttention 2.8.3。

## 数值差异已在回归范围内修复

先定位旧长 trace 的首次分歧，再固定生成历史，对比不同调度形状与 FP32 输出投影。
FP16 输出投影存在候选舍入并列，但仅改投影不足以解决长生成分歧。
新增固定分块 linear、固定时序归约 attention、FP32 logits 后，三个种子的五种调度输出全部相等。
共 360 次请求执行、34,370 个自由生成输出 token；没有 teacher forcing 或放宽 token equality。
独立 Transformers FP32 重算也支持两个已知分歧位置的修复结果。

完整过程与失败消融见 [数值正确性](NUMERICAL_CORRECTNESS.md)。第三版完整门禁 77 项通过；冻结第四版完整门禁 **78 项通过，61.54s，零失败/跳过**。
这不是所有模型、dtype、设备上的一致性保证，也不是自然语言质量评测。

## 公平比较条件

全部策略使用同一个固定归约后端、模型、FP16、CUDA Graph 设置、64 个 KV blocks、每块 256 token、
每步最多 16 条序列、全局 2048 token。64 blocks 是刻意限制的压力池，不代表 24GB 显存全部容量。
native 仅表示同一 fork 的上游调度策略，不是未经修改的原版二进制。

`gpu_compare.py` 每组加载一次模型，各策略运行前重建 scheduler/cache manager，执行相同专门预热，再重建调度器计时。
随机打乱配置运行顺序；计时包含调度、输入准备、GPU 执行、采样与尾部 drain，排除模型加载与专门预热。
新形状首次编译仍可能产生离群值，因此报告重复中位数及范围，不能把少量样本当显著性检验。
到达为开放环，延迟从原定到达计算，包含等待当前 step 完成的时间。

goodput = 同时满足 TTFT ≤ 1000ms、请求平均 TPOT ≤ 50ms 的完成请求数 / 整段重放时间。
ITL P99 另列，不能与平均 TPOT 或 goodput 混称。所有 trace 为合成 token 请求，没有 HTTP 或 tokenizer 开销。
每组检查输出 token 序列相等；本地审计再次检查代码与配置、trace hash、请求完整性、时间单调性及全部输出。

## 保留的调参失败结果

调参仅使用 seed 7，每种负载 24 请求。训练结果不得当独立评估结果。

| 迭代 | 参数 / 负载 | CUDA 报告 | 相对最佳普通 fixed 的 goodput |
|---|---|---:|---|
| train-v1 | target40ms / initial512；rate15；mixed、burst；各重复3次 | 54 | cost：mixed -5.02%，burst -2.68% |
| train-v2 | target50ms / initial2048；rate30；mixed、burst、pressure；各重复3次 | 99 | cost：mixed +0.17%，burst -1.55%，pressure -0.21% |

两组全部输出相等。train-v2 的 +0.17% 接近噪声，不作为胜出证据。
成本模型解决了旧 AIMD 的“20ms 目标低于约 28ms 固定开销，持续缩 chunk”问题，但尚未证明动态预算本身优于调优后的固定预算。
合并小 Prefill 的 24ms / 96ms 延后窗口也没有稳定收益，失败结果均保留。

## 发现并处理第二个瓶颈

长输出占满所有 Decode 执行槽位时，旧混合调度器即使仍有 token 预算，也不能开始新 Prefill。
train-v2 的 pressure seed7 中，普通 fixed2048 的 TTFT P99 约 2201ms、goodput 约 3.04 请求/s。
这时优化 token 预算作用很小。

第三版新增 `admission_wait_ms=100`：队首等待达到阈值且 KV 可以准入时保留一个 Prefill 槽位，
其余槽位仍推进 Decode；running 请求轮转，避免固定队首长期占用执行槽位。
驻留请求可以多于当步执行上限，但每步序列数、token cap、KV 物理容量都不变。
新机制可单独配 fixed；五种 `fixed-*-admit` 是必要的更强消融，不能把它的收益全部归给成本拟合。

第三版 train-v3 共84报告（14配置 × 3负载 × 2重复），全部输出相同。
pressure 的 cost-admit 相对普通最佳 fixed 为 +27.46%，但相对 fixed2048-admit 为 -5.67%；mixed、burst没有明显收益。

第四版加入预计自然释放槽位时间与最多4个 Prefill 槽位：当请求预计即将结束时避免不必要的轮转/准入；
多个等待请求可共享一次 Prefill 执行。预测由 Decode-only EWMA 和剩余 max_tokens 上限计算，实际 EOS 提前结束可能使它偏保守。

train-v4 共84报告，全部输出相同。固定2048 token预算 + aware准入 相对普通最佳fixed：mixed +0.85%，burst -0.03%，pressure +34.29%。
cost-aware：mixed -3.39%，burst -2.74%，pressure +31.17%；相比带同样aware准入的最佳固定预算仍分别为 -4.21%、-2.72%、-2.32%。
这支持把动态准入作为主要研究点，不能证明动态 token 预算是吞吐收益来源。

该训练收益是 **goodput**，不是总 token 吞吐加速：pressure 的普通 fixed2048 满足 SLO 的比例为66.7%，
aware准入为95.8%，但生成 token/s 的两次中位数由约1790降到约1672（约-6.6%），抢占由0增到8。
对照的 native goodput 约4.286，高于 aware准入约4.093。不能把“相对普通 fixed 的 goodput 提高34.3%”
写成“比原版 nano-vLLM 推理快34.3%”。

- 简单等待准入在pressure/101比预测准入更快；完成时间预测没有稳定额外收益，不应把更复杂当成更好。

主要得到验证的机制是**按队列状态调整Prefill准入槽位并轮转Decode**。在线动态token预算和额外完成时间预测保留为实验开关；没有证据支持把它们默认叠加用于提升goodput。

## 扩大 KV 池后的稳健性复测

128-block 复测也已完成：84报告，2016次请求执行、738,318输出token，全部输出相同。
只与同一128-block条件下的基线比较；参数、种子、到达率和SLO均按提前冻结的配置执行。

| pressure seed | 普通最佳 fixed | 2048 + 简单准入 | 2048 + 预测准入 | 相对普通 fixed | 动态预算 + 预测准入 | native |
|---|---:|---:|---:|---:|---:|---:|
| 101 | 3.347 | 5.484 | 5.448 | +62.75% | 5.407 | 5.087 |
| 307 | 3.158 | 5.510 | 5.582 | +76.74% | 5.572 | 4.776 |

单位为goodput请求/s。普通 fixed 的SLO达标率为66.7%，两种准入方案均为100%，以上配置都没有抢占。
预测准入的生成token/s相对普通fixed分别提高8.50%、17.83%，TTFT P99由1741/1995ms降到249/201ms。
该池容量下的收益同时包含总吞吐改善，不能与64-block中主要提升SLO达标率的情况混为一谈。

相对同fork的native，预测准入goodput分别约+7.08%、+16.88%；但ITL P99约41.7/32.9ms，高于native约6ms。
同样预测准入的最佳固定预算仍是1024，动态预算分别低1.58%、0.26%，未证明动态token预算的额外优势。
简单等待准入与完成时间预测仍各有高低，差异很小，不声称预测版稳定胜过简单版。

## 可交付结论与边界

- 长负载数值分歧已经在既定回归范围内修复；固定数学后端是公平比较的共同前提。
- 新增等待时间/负载驱动的Prefill槽位准入与Decode轮转，在独立长输出负载上胜过普通固定预算扫描的最佳值；扩大KV池后收益仍存在。
- 主要收益来自槽位准入，动态token成本模型没有胜过带同样准入的强固定基线；额外完成时间预测也未稳定胜过简单等待阈值。保留为显式实验开关，不默认叠加。
- 不能声称所有负载、所有尾延迟或所有引擎普遍加速。有限单卡/小模型、合成请求、已知max_tokens上限、max_num_seqs=16，实际EOS、真实文本、HTTP层、大模型与更大执行并发仍需另测。

本轮全部性能实验657报告，独立评估及稳健性复测占336报告（8064请求执行，1,851,360输出token）。
每个trace/资源组合内输出逐token相同。不是336个独立负载：独立输入种子只有101、307，各自3种形状负载；128-block复测重复使用pressure输入。
