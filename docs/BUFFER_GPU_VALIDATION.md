# 分阶段统计与输入复用：RTX 3090 实验

日期：2026-10-22；RTX 3090 单卡；Qwen3-0.6B / FP16；CUDA Graph；batch_invariant=True。

## 结论

最终连续缓冲区版（v3）有小幅实际收益：10 个纯 Decode 场景的配对吞吐提升中位数为 **0.60%–4.48%**，6 个端到端场景为 **0.98%–3.52%**。50 对 micro 与 18 对 e2e 重复均为正。

单纯复用六个独立输入张量的 v2 基本无收益；依据分阶段结果将六次小 H2D 合并为一次，并让 CUDA Graph 直接绑定 slab 视图后才得到提升。调度策略、模型算子和 KV 容量均保持相同。

Mac 本地 **126 passed / 7 skipped**；RTX 3090 **133 passed**。最终版 148 次采样/性能运行全部输出一致，其中 e2e 为 864 次请求执行；另核对这 148 次与 v2 的输出和 trace 一致。原始 manifest 与当前源码 hash 匹配。

## 实现与比较方法

- 新增 CPU 阶段计时及延后收集 CUDA events；正式性能计时关闭 profiling。
- pinned CPU / GPU 各一个 byte slab，按 8 字节对齐提供六个 typed tensor 视图。每次纯 Decode 一次 H2D，跳过旧路径额外的 Graph D2D 拷贝。
- 同进程同模型，固定随机种子打乱 A/B 顺序，每次预热；两组均预分配同一个输入池，KV blocks 相同。
- micro：batch=1/4/16/32/64，初始 context=32/1024，预热后测量 96 步；每场景 5 对重复；384 KV blocks。
- e2e：mixed/burst/pressure × seeds 101/307，每组 3 对重复、每次 24 请求；128 KV blocks，max_num_seqs=16，固定 prefill_budget=2048 加原有自适应槽位准入。
- 延迟阈值为 TTFT<=1000ms 且请求平均 TPOT<=50ms；不是要求每次 ITL<=50ms。

- v3 输入包 SHA256：`15930c01272a2da56a3c6e45367ffd45eeb85ebac72bc3fe1ef72c0b828b0eae`。
- CUDA 12.8 / torch 2.8.0 / triton 3.4.0 / flash-attn 2.8.3；全部环境见各 suite 的 manifest。
- 此报告只测 Qwen3 单卡、小模型、合成 token 负载；随后完成同源码 [Llama GPU 验证](LLAMA_GPU_VALIDATION.md)。大模型、真实服务和 BF16 仍未验证。
- 只优化纯 Decode；混合 Prefill/Decode 保留旧路径。仍等待 sampler.tolist()，未实现异步流水。
- 整块上传用少量多余字节换更少调用；极大配置可能稀释收益，需要重新测量。
- e2e 调度参数一样，但更快的 step 会改变请求到达落点和反馈，所以端到端收益还包含这一间接效应。
- 这不改变“动态 token 预算未胜过同准入强固定基线”的原结论，也不能与历史 goodput 增幅直接相加。默认开关仍为关闭，按模型和负载选择启用。
